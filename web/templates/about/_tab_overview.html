TS-Lens is a web-based time-series pattern discovery tool that connects upload → preprocessing → exploration (search · clustering) → interpretation → labeling in one workspace.

TS-Lens Core Flow
Users express a target pattern through natural language, sketching, example intervals, presets, or cluster representatives. TS-Lens turns those inputs into inspectable waveform queries or compares them against real intervals, retrieves similar segments, and connects selected results to natural-language explanations, label baskets, and reusable custom presets.
Paper framing: Describe → Generate → Search → Explain → Curate. TS-Lens is not a new forecasting model; it is a multi-modal interface for zero-shot time-series pattern discovery.
View-Adaptive Query Modes
The system automatically adapts available search modes based on your data view:
  • Continuous View: Select (chart drag), Sketch (freehand drawing), Text (LLM) — sliding window search on the full timeline
  • Segment View: Sample (click card), Sketch (freehand drawing), Preset (7 built-in + custom), Cluster (Fast/Shape/Semantic AI), Text (LLM)
This clean separation ensures each mode operates on the appropriate data structure without confusion.

Pattern Search

6 input paths: Text (natural language → rule-based pre-pass, then a local model or external LLM generates the shape), Preset (7 built-in + custom), Select/Sample (real waveform QBE), Sketch (freehand drawing), Cluster (unsupervised discovery). Multi-column search, 4 distance functions (Euclidean/DTW/Cosine/Shape), ChatTS segment description (reverse).

Details and usage scenarios: See Pattern Search tab

Labeling

Build a pattern library by accepting/rejecting search results. Label Basket (Draft → Confirmed) workflow. Auto-refine query using the average shape of confirmed segments. Save cluster centroids as custom presets. Cross-column pattern correlation analysis.

Details and usage scenarios: See Labeling tab
☷

Data Management

The Data Management page has three tabs: Datasets, Upload and Model Connection. Upload accepts a single file or a folder (one source per file, or merged into one series by time), auto-detects encoding and delimiter, and lets you choose how duplicate timestamps are handled (reject, first, last, mean, shift). If every timestamp appears exactly k times, it reports that the data looks like k regional files merged together. Deleting a dataset also removes its linked preprocessing results, labels, baskets, presets, caches and files, after a DB backup is made. Bundled public data includes Elia (Belgian TSO) wind generation and forecasts for 2015–2026 prepared as five regional hourly CSVs, plus Sangmyeong wind farm and Haengwon met-mast data.

✨

AI Metadata Inference

Once an admin connects an external LLM (Anthropic Claude or an OpenAI-compatible server) in the Model Connection tab, a switch at the top of the Upload tab turns AI metadata inference on per upload (off by default, last choice remembered). When on, it fills dataset key, name, description, location, facility, capacity, sampling interval, characteristics and tags, plus column labels, units, descriptions and min/max; AI-filled fields get a red border that disappears once edited. Every metadata field has an ⓘ help popup, and column min/max define the physical range used by preprocessing to filter out-of-range values. The API key stays in a server-side file and only its last four characters are shown; estimated cost triggers a warning at $10 per month and a hard limit at $100 (configurable).

⚿

Sign-in and Models

Sign-in is enabled only when accounts exist in config/local/users.yaml on the server. There are two roles, admin and user; only admins can use the Upload and Model Connection tabs. Accounts are not created in the UI; an admin registers them with tools/set_password.py. The default model for segment explanation is ChatTS-14B from ByteDance Research: it runs in 8-bit on a separate server that shares the GPU, loads on request and unloads after five idle minutes. An external LLM can also be selected for explanation and generation.

The Problem
1

There is no Ctrl+F for time series

Text can be searched by keywords, but there is no way to find "similar shapes" in numerical waveforms. It is impractical for engineers to scroll through tens of thousands of data points visually, and segments will inevitably be missed.

Reality8,760pt (1 year) × 24pt window = 8,737 candidates. Impossible by eye.
2

Same shape, but labeled "different"

Winter at 50kW and summer at 100kW differ in magnitude, but the curve shape is identical. Simple value comparison cannot capture such patterns. The scale must be removed to compare pure shape only.

SolutionZ-score normalization removes scale → compare shape only

A single variable is not enough

In real-world settings, multiple variables move together — temperature, irradiance, power output, etc. Looking at a single column misses correlations. Distances across columns are equally averaged to compute overall similarity.

Real-World Data
8

Real-world data is never clean

Sensor failures, communication outages, extreme values. Field data without missing values and outliers is virtually nonexistent. Searching without preprocessing yields unreliable results.

Solution3 stages: extreme value handling → time gap filling → 8 imputation methods (incl. MOMENT FM)
9

The analysis unit is not fixed

Sometimes by hour, sometimes by day, sometimes the entire segment. You need to freely concatenate and re-split data depending on the analysis goal.

Example3 daily segments → Concat → search for patterns across all → re-split by hour
10

Data formats vary widely

Datetime-based continuous time series, step-based batch data, non-contiguous segment collections. A single tool must handle all these formats to be usable in the field.

ExampleMotor runs (step 1~148) × 8 collection · DTW variable-length comparison
Knowledge Loop
11

Domain experts do not write code

The people who best understand the patterns are the field experts. But they cannot implement DTW algorithms or write Python scripts. A tool is needed where uploading a CSV and a few clicks produce search results.

FlowUpload → select columns → drag/preset/natural language → results
12

Finding once is not the end

The initial query created by LLM or preset is an idealized approximation. When you Accept the segments you actually want from the results, their real data is averaged to automatically generate a more realistic query shape. Repeating this process progressively adapts the query to your data.

Example"sudden drop" search → Accept 6 of 10 → Refine → query updated to actual drop shape
13

Expert judgment is being lost

Even when an experienced engineer determines "this is abnormal," that knowledge goes unrecorded and is lost. When accepted segments accumulate in the pattern library, expert judgment becomes a reusable data asset.

Example"clear sky" 168 instances accumulated → CSV export → ML training labels

Four specialized agents each perform their own role. Inter-agent connections are made through Flask routes, and the user directly controls the workflow flow.

Data Curator

Data Curator

Cleans raw data and analyzes its structure to prepare it for exploration.

  • Preprocessing pipeline (extreme values, gaps, imputation incl. MOMENT FM)
  • Data quality diagnosis (NaN, range, outliers)
  • FFT periodicity analysis
  • Sampling interval detection / segment splitting
Raw CSV → Clean Data (DB)

Interpreter

Interpreter (ChatTS · LLM)

Bidirectionally converts between natural language and time series shapes. Recognizes domain metadata.

  • Forward: Text → Shape (NL-to-Shape)
  • Reverse: Shape → Text (segment description)
  • Independent shape generation per column (metadata-aware)
  • Explain: ChatTS-14B (separate GPU server, loaded on demand)
  • Generate: rule-based pre-pass + local model or external LLM (Claude or OpenAI-compatible)
Natural language / segment values ↔ Shape / description

Retriever

Retriever

Mathematically compares query shapes with data segments to find similar intervals.

  • Sliding window / segment / preset auto-classification
  • 4 distance functions (Euclidean / DTW / Cosine / Shape)
  • Z-score normalization + NaN handling
  • Multi-column search
Query Shape + Data → Ranked Results

Labeler

Labeler

Defines patterns through user feedback and accumulates the pattern library.

  • Accept / Reject feedback loop
  • Refine: instance average → improved Shape
  • Pattern library CRUD
  • Export labeling results as CSV
Results + Feedback → Pattern Library

Key Differentiators
  • Generate-based NL query: Natural language is converted to an inspectable waveform shown with the search results and its model provenance, rather than hidden in an opaque vector.
  • Bidirectional Text↔TS: Both Text→Time-Series (query generation) and Time-Series→Text (segment explanation) in one workspace.
  • Human-in-the-loop curation: Useful results are collected in the Label Basket, while reviewed query shapes or cluster medoids can be saved as Custom Presets for reuse rather than one-time lookup.
